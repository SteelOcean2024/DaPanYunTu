# 06 · 大盘云图（实时市场热力图）

> 把全市场 5500+ 只个股按「一级行业 → 二级行业」铺成 treemap：
> **面积代表规模，颜色代表涨跌幅**，一眼看清板块轮动与权重分布。
> 数据每 5 秒自动刷新。
>
> 姊妹页是 [`07_行业情况.md`](07_行业情况.md)——云图看**结构**（今天市场长什么样），
> 那一页看**强弱**（哪个板块真在动、动到哪一步）。代码上两者共用同一份行情快照。

---

## 一、它解决什么问题

看盘时最费劲的一件事是「今天市场到底是什么结构」：
指数只告诉你加权后的一个数字，涨跌家数只告诉你宽度，
但**钱在往哪个板块走、哪个权重股在拖指数**——这些从数字上看不出来。

云图把三维信息压到一张图上：

| 视觉通道 | 编码的信息 |
|---|---|
| 面积 | 规模（总市值 / 流通市值 / 成交额，可切换） |
| 颜色 | 涨跌幅（红涨绿跌，越深幅度越大） |
| 位置 | 行业归属（一级行业 → 二级行业 → 个股） |

## 二、架构

```
        慢路径（几分钟级，缓存 7 天）
        ┌──────────────────────────────────────┐
        │ 申万行业树  31 个一级 / 131 个二级      │
        │ 成分股      index_component_sw        │
        │ 全市场代码表 stock_info_a_code_name    │
        └───────────────┬──────────────────────┘
                        │  runtime/data/industry/*.parquet
                        │  runtime/data/heatmap/*.parquet
                        ▼
        快路径（秒级，后台线程每 5 秒一轮）
        ┌──────────────────────────────────────┐
        │ 腾讯批量行情  5580 只 / 约 1.1 秒       │
        │   ↓ 挂行业                            │
        │   ↓ 组装三级嵌套树 + 汇总               │
        │ 内存快照（预先序列化成 bytes）           │
        └───────────────┬──────────────────────┘
                        │  HTTP（只读快照，不碰网络）
                        ▼
        ┌──────────────────────────────────────┐
        │ 浏览器：Canvas squarified treemap      │
        │ 缩放 / 平移 / 悬浮 / 板块聚焦 / 定时轮询 │
        └──────────────────────────────────────┘
```

**关键设计：慢路径和快路径彻底分离。**

行情接口只给代码、价格、市值，**不给行业**；而云图的核心恰恰是行业分块。
如果每 5 秒都去拉一次行业成分股（约 50 秒），实时刷新就无从谈起。
所以行业归属单独缓存（7 天有效），每次刷新只补价格/涨跌幅/市值。

## 三、数据源选型

### 行情：为什么用腾讯，不用东方财富

| 数据源 | 全市场耗时 | 问题 |
|---|---|---|
| **腾讯** `qt.gtimg.cn` | **1.1 秒**（8 并发 × 600/批） | 无 |
| 东财 `push2` | 一次请求返回全部 | **按 IP 限流，触发后 5~40 分钟不可用** |
| 新浪 | 分页拉取，约 40 秒 | 太慢 |

云图要每几秒刷一次，东财必然被限流（本项目已经踩过这个坑）。
腾讯接口一次可带 600 只，实测无频控。

### 行业：申万分类

`akshare` 封装的申万研究所公开接口：

- `sw_index_first_info()` → 一级行业 31 个
- `sw_index_second_info()` → 二级行业 131 个（带「上级行业」字段，可直接挂树）
- `index_component_sw(symbol="801016")` → 某行业成分股

**坑**：`index_component_sw` 只认纯数字代码，带 `.SI` 后缀不报错、直接返回空表。

## 五、前端渲染

### 为什么用 Canvas 而不是 DOM

全市场 5580 个方块。用 DOM 的话每次刷新要重建 5580 个元素，
浏览器的排版 + 重绘会明显卡顿；Canvas 一次绘制就能搞定，
缩放平移也只是改一个变换矩阵，不触发任何 layout。
代价是要自己做命中检测——用线性扫描（5580 次比较）足够快。

### squarified treemap

为了让方块尽量接近正方形（细长条既难看又难读），采用 squarified 算法：
按面积降序，逐块尝试加入当前「行」，若加入后最差长宽比变好就继续加，变差就把当前行铺下去。

**最容易写错的地方：铺排方向。**

> 始终沿矩形的**短边**铺。
> - 矩形竖长（`h >= w`）→ 短边是宽度 → 铺一条**横向**带
> - 矩形横长（`w > h`）→ 短边是高度 → 铺一条**纵向**带
>
> 写反了就会渲染成一层层横条，而不是方块。这个 bug 本项目实际踩过。

### 标签渲染：为什么第一版是「马赛克」

这是本项目**最值得记录的一次迭代**——同一份数据、同一套布局，
只改文字渲染策略，观感从「一片色块」变成「能看清每只股票」。

**问题的算术**：5580 只个股铺在约 85 万 CSS 像素的画布上，
平均每只只有 153 px²，**中位方块只有 6×5 像素**。

第一版的门槛是「宽度 ≥34px 且完整名称放得下」，结果：

| | 第一版 |
|---|---|
| 有字的方块 | 71 / 5580（**1.3%**） |
| 观感 | 一片纯色块 = 马赛克 |

**实测参考实现**（`beta.dapanyuntu.com`，用 hook 拦 `fillRect`/`fillText` 数出来的）：

| 指标 | 参考实现 | 第一版的我 |
|---|---|---|
| fillRect 调用 | 5698（≈ 全部个股） | 5580 |
| 中位方块边长 | 5.1 px | 5.6 px |
| **fillText 调用** | **903** | 142 |
| 不同文本数 | 805 | 71 |

关键结论有两条：

1. **参考实现也没有「少画股票」**——它同样把 5566 只全铺出来了，
   中位方块一样是 5 px。差别完全在文字渲染。
2. **它的字号能小到 5.5 CSS px**。因为 canvas 是 `DPR=2` 的背衬，
   5.5 CSS px 实际渲染成 **11 个设备像素**，在屏幕上依然清晰可读。
   我第一版把下限卡在 6.5px，导致「兆易创新」这种四字名放不下，
   只能截成「兆易…」，于是干脆整块不画。

**改法：四级降级，能画就画。**

| 屏幕尺寸 | 布局 | 字号范围 |
|---|---|---|
| ≥54 × ≥44 | 三行：名称 / 涨跌幅 / 价格 | 8 ~ 30 px |
| ≥20 × ≥20 | 两行：名称 / 涨跌幅 | 5.5 ~ 14 px |
| ≥34 × ≥12 | 一行：名称 + 涨跌幅（左右对齐） | 5.5 ~ 11 px |
| ≥11 × ≥9 | 一行：名称（放不下才截断） | 5.5 ~ 10 px |
| 更小 | 不画 | — |

字号用「字符宽度估算 + `measureText` 校正」求最大可容纳值，
而不是从 30px 线性试到 5.5px——后者在 2000 个方块上会变成几万次测量。

另外，**截断到只剩一两个字时不加省略号**：「兆…」比「兆」更占地方也更难认，
参考实现在小方块上就是直接显示单字（「长」「中」「N」）。

改完之后：

| | 第一版 | 现在 | 参考实现 |
|---|---|---|---|
| 有字方块 | 71 | **845** | ~800 |
| fillText 调用 | 142 | **1161** | 903 |
| 截断（含省略号） | 104 | **10** | — |
| 完整四字以上标签 | 312 | **429** | — |

### 绘制性能：把 `clip` 拿掉

标签从 71 个涨到 845 个之后，一帧要画 5580 个 `fillRect` + 1161 次 `fillText`，
最初的做法是每个有标签的方块都 `save() → rect() → clip() → restore()`，
结果全图一帧 30.4 ms、拖拽 38 ms（26 fps），明显不跟手。

**`clip()` 是这里最贵的一步，而且它根本没解决问题**：
文字是按方块尺寸算好的、本来就不会溢出，真正隔开相邻方块文字的是那
1 像素的缝隙。去掉 clip 之后：

另外两处优化：

- **`colorFor` 按 0.1% 精度缓存**——一帧取 5580 次颜色，
  每次都新建 `rgb(...)` 字符串的话光分配就是可观开销；缓存后实际不同颜色只有几百种。
- **`ctx.font` 比对后再赋值**——赋值会触发字体串解析，密集区域相邻方块字号常常相同。

| | 优化前 | 优化后 |
|---|---|---|
| 全图每帧 | 30.4 ms（33 fps） | **10.5 ms（95 fps）** |
| 拖拽每帧 | 38 ms（26 fps） | **14.8 ms（68 fps）** |
| 放大后每帧 | — | 8.3 ms（视口裁剪生效） |

### 色阶

采用「中间灰、两端深」的三段插值：

| 涨跌幅 | 颜色 |
|---|---|
| 0% | 灰 `rgb(74,74,74)` |
| ±2% | 中等饱和红/绿 |
| ±4% 以上 | 深红 `rgb(123,26,18)` / 深绿 `rgb(20,81,44)` |

极端涨跌用**深色**表示「强烈」。如果越极端越亮，满屏涨停时会亮得看不清文字。

### 坐标系

- **世界坐标** = 布局坐标系，尺寸等于画布 CSS 像素
- **屏幕坐标** = `world * view.scale + view.t`

缩放平移只改 `view`，不动布局，所以拖动是零成本的。
滚轮缩放以光标为锚点（先反算光标下的世界点，缩放后再把它移回原位）。

## 八、踩坑记录

### 1. 交易所不能用代码反推

最初用 `exchange_of(code)` 从 6 位代码判断交易所，结果：

- `399001`（深证成指）→ 抛异常 → 指数被静默丢弃
- `000001` 既是上证指数又是平安银行 → 撞车

**正解**：腾讯报文里已经带了市场前缀（`v_sh600000` / `v_bj920002`），
直接取前缀，不要反推。指数的代码规则和个股根本不同。

### 2. 北交所 92 号段

北交所 2024 年启用 `920xxx` 新号段，原来的判断只覆盖 `4/8` 开头，
导致 `920002` 被判为「无法判断交易所」而丢弃。
同时 `900xxx` 是上海 B 股（不是北交所），不能把 `9` 一律归给北交所。

### 3. 腾讯字段单位

| 字段 | 单位 | 换算 |
|---|---|---|
| `[37]` 成交额 | **万元** | ×1e4 → 元 |
| `[44]` 流通市值 | **亿元** | ×1e8 → 元 |
| `[45]` 总市值 | **亿元** | ×1e8 → 元 |
| `[36]` 成交量 | 手 | ×100 → 股 |

不换算的话云图面积会差好几个数量级。

### 4. squarified 方向写反

见上文「前端渲染」一节。症状是渲染成一层层横条。

### 5. `pandas` 类型漂移

上游空值会让数值列变成 `object` dtype，后续比较/求和会出意外结果。
`fetch_quotes` 末尾统一 `pd.to_numeric(...).astype("float64")` 强制收敛。

### 6. `window.open` 带 features 参数 → 点了没反应

最初点击个股用的是 `window.open(url, '_blank', 'noopener')`，用户反馈「点不开链接」。
在 Chromium 里用**真实鼠标点击**复现并逐一对比：

| 写法 | 结果 |
|---|---|
| `window.open(url, '_blank', 'noopener')` | 被当作**弹出式窗口**请求，容易被弹窗拦截器吃掉；即便开出来也是独立窗口，常落在主窗口后面，看着就是「点了没反应」 |
| `window.open(url, '_blank')` | 开成当前窗口的新标签页 |
| `<a href target="_blank" rel="noopener">.click()` | 走普通导航，稳定开成新标签页 |

**正解**：用 `<a>` 元素点击，不要给 `window.open` 传第三个参数。

这里有个容易误判的坑：`window.open(url, '_blank', 'noopener')` 返回 `null` 是
**设计如此**（noopener 就没有 opener 引用），**不能拿返回值判断是否被拦截**。
要判断只能看浏览器里是否真的多了一个 target（CDP `Target.getTargets`）。

### 7. 窄屏下侧栏把画布挤成一条缝

侧栏原本是固定 236px 的 flex item，窗口一窄，画布只剩几十像素宽——
这就是「没有伸缩性」的直接样子（对比图见
`docs/screenshots/64_云图窄屏_修复前后对比.png`）。

**正解**：`@media (max-width:900px)` 下把侧栏改成 `position:fixed` 的浮层抽屉，
配汉堡按钮 + 遮罩；并用 `ResizeObserver` 监听**画布容器**而不是 `window.resize`——
侧栏开合、浏览器缩放、进入全屏都不触发 `window.resize`，但画布容器一定会变。

### 8. 配色是「两端鲜艳、中间暗」，不是「越极端越暗」

早期实现把极端涨跌幅映射成**更暗**的颜色，方向反了：
满屏大跌时整张图糊成一片深色，「哪里跌得最狠」反而看不出来。

参考实现（大盘云图）的色阶是 **0% 暗蓝灰 `#414554`，±4% 最鲜艳**。
本工程的 `COLOR_STOPS` 是逐点采样它的**实际色块填充色**（不是图例）标定的，
校验方式：同一只股票取像素主色对比，例如工商银行 +1.06% 参考站 `#c03e44`、
本工程 `#c23c42`。

### 9. 缩小之后四周全是黑的

原本 `MIN_SCALE = 0.5`，但布局在 `scale=1` 时就已经**正好铺满画布**
（`buildLayout` 传进去的就是画布宽高）。所以再往下缩只会让整张图变小、
四周露出画布底色——用户看到的就是一圈黑边。

同一个毛病**拖拽也会犯**：`scale=1` 时把图拖走，另一侧同样露黑。

**正解**（`web/heatmap/app.js`）：

- `MIN_SCALE = 1`——全图就是最小缩放，不存在「比全图还小」的状态；
- 加 `clampView()`，把平移量夹进 `tx ∈ [W*(1-scale), 0]`（`ty` 同理）。
  `scale==1` 时区间退化成 `tx == 0`，即全图状态下拖不动——这是对的，
  此时本来就没有可拖的余量。
- `clampView()` 在四处调用：滚轮缩放后、拖拽每帧、`focusRect()` 聚焦后、
  `resizeCanvas()` 重排后。漏掉任何一处，那条路径上就会重新露出黑边。

实测：连滚 25 次滚轮向下，`scale` 停在 1、`tx/ty` 停在 0，四角像素全是色块；
放大到 80 倍后两个方向各猛拖一次，正好停在 `W*(1-scale)` 边界上，四角仍是色块。

对比图：`docs/screenshots/68_云图缩小_修复前后对比.png`

### 10. 放大后方块里的字不跟着变大

症状：缩放越大，方块越大，字却始终是那么大，方块边缘到文字空出一大片。

根因是 **单位混用**。canvas 处在 `ctx.scale(scale, scale)` 变换下，所以：

- `setFontScreen(f, w, scale)` 里的 `f` 是**屏幕**字号（内部除以 `scale` 才是世界字号）；
- 而 `availW = t.w - …` 是**世界**单位。

`fitFontSize` 的初始估算写成了 `availW / textWeightUnits(text)`——
拿世界宽度当屏幕字号用，**漏乘 `scale`**。于是字号恒等于「按全图尺寸算出来的值」，
放大多少倍，字相对方块就小多少倍。

压在它上面的还有第二个错：四档字号各有一个**绝对**屏幕像素上限
（`Math.min(sh * 0.24, 30)`、`…, 14`、`…, 11`、`…, 10`），
以及行业标题带的 `clamp(h * 0.62, 9 / scale, 15 / scale)`。
这些上界在放大后会把字号钉死。实测「建设银行」这一块：

| 缩放 | 方块屏幕尺寸 | 修复前字号 | 修复后字号 |
|---|---|---|---|
| 1× | 331 × 411 | 30 px | 76 px |
| 4× | 1325 × 1645 | 30 px | 324 px |
| 40× | 13252 × 16446 | 30 px | 3312 px |

修复后 `字号 / 方块高` 恒为 0.20，与缩放无关。

**正解**：

- 估算改成 `(availW / textWeightUnits(text)) * scale`——把世界宽度换算成屏幕字号；
- 去掉那些**绝对**像素上限，只保留「按方块屏幕尺寸的比例」（`sh * 0.24` 等）
  和宽度反推的上限。比例上限本身与缩放无关，绝对上限才会有问题；
- 行业标题带改用 `headerFontSize()`：高度比例 + 宽度反推 + 屏幕像素下限，
  同样不含绝对上限；
- 左右留白从固定 3 屏幕像素改成 `max(3 / scale, t.w * 0.08)`。只留固定 3px 的话，
  放大后 1400px 宽的方块里文字会紧贴两边，相邻方块看着就粘在一起。
  修复后文字占方块宽度稳定在 92%。

修完这一条，标签的观感只取决于方块的**屏幕**尺寸，与缩放无关——
这正是「跟随方块放大」该有的样子。

## 九、已知限制

1. **未分类个股**：申万分类不覆盖全部 A 股（北交所、次新股），
   当前约 358 只归入「未分类」板块。这是**如实呈现**而不是丢弃——
   丢弃会让云图个股数对不上大盘，用户会以为数据缺了。
2. **无 ETF / 可转债 / 港股视图**：接口契约已预留 `market` 字段，数据层待补。
3. **无「较昨日同期」成交额对比**：需要连续运行积累基线，暂未实现。
4. **停牌股被剔除**：现价为 0 的个股不参与云图（面积会退化成零宽矩形）。
5. **非交易时段**：显示的是最近一个交易日的收盘快照，颜色不会跳动。
