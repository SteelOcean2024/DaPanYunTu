# 06 · 开发与部署

---

## 一、环境准备

```bash
python -m pip install -r requirements.txt
```

依赖很少，故意如此：

| 包 | 用途 |
|---|---|
| pandas | 数据处理 |
| pyarrow | Parquet 读写（行业映射缓存） |
| requests / akshare | 拉行业分类（慢路径） |
| pytest | 测试 |

**HTTP 服务不用任何框架**——标准库 ThreadingHTTPServer 够用，少一个依赖少一次版本冲突。

## 二、首次上手（三步）

```bash
# 1. 建行业映射缓存（约 50 秒，7 天有效；不建的话服务起不来）
python scripts/build_industry_map.py

# 2. 起服务
python scripts/heatmap_server.py

# 3. 打开
#    云图     http://127.0.0.1:8770/
#    行业情况 http://127.0.0.1:8770/sector
```

可选参数：

```bash
python scripts/heatmap_server.py --port 8770 --interval 5 --metric total_mcap
python scripts/build_industry_map.py --force      # 忽略 7 天缓存强制重建
```

## 三、改代码的流程

### 改「口径」（指标算法）——这是最危险的一类改动

```
1. 先改 learning/03_指标口径.md           ← 定义先行
2. 改 Python：src/analysis/sector.py 或 src/heatmap/treemap.py
3. 改 JS：   web/shared/market.js 对应函数
4. 跑两边对齐验证（见 05_注意事项.md 第一节的控制台代码）
5. 跑 pytest
```

**第 3、4 步不能省。** 只改 Python 的话，线上会是错的数据，而且不报错。

### 改「展示」（颜色 / 布局 / 文案）——安全很多

- 颜色：web/heatmap/app.js 的 COLOR_STOPS（图例自动跟着变）
- 字号与布局：同文件的 computeLabelPlan / fitFontSize
- 行业情况页整页：web/sector/index.html（单文件，内联 CSS/JS）

改完直接刷新页面即可，服务不用重启（静态文件每次请求都从磁盘读）。

### 改「服务端」

改 scripts/heatmap_server.py 或 src/ 下的 Python **必须重启服务**。

## 四、测试

```bash
python -m pytest -q
```

| 文件 | 覆盖 |
|---|---|
| tests/test_heatmap.py | 30 个：代码规范化、行情解析、云图组装、单位换算 |
| tests/test_sector.py | 15 个：板块强度指标的**纯函数**测试（含边界与限流） |

合计 **45 个**。都不联网、不落盘（落盘那两条用 tmp_path 隔离）。

**新加指标一定要补测试。** 板块指标是纯函数，测起来很便宜——
构造一个小 DataFrame，把中位数、加权、宽度、RS 的期望值手算出来断言即可（见 test_sector.py）。

## 五、部署到 GitHub Pages

```bash
git add -A && git commit -m "..." && git push
```

推送后 `.github/workflows/pages.yml` 自动把 `web/` 发布到 Pages，约 30 秒。

### 首次部署需要人工做一次

仓库 **Settings → Pages → Source** 选 **GitHub Actions**。
**这一步只能人来点**——`GITHUB_TOKEN` 没有 `administration` 权限，建不了 Pages 站点，
`configure-pages` 的 `enablement: true` 也救不了（实测过）。

### 行业分类变了要重导

申万半年调一次分类。发现行业对不上时：

```bash
python scripts/build_industry_map.py --force   # 重建缓存
python scripts/export_web_data.py              # 重新导出给前端的 JSON
git add web/data/industry-map.json && git commit -m "更新行业映射" && git push
```

## 六、排查手册

### 症状 → 原因 → 处理

| 症状 | 原因 | 处理 |
|---|---|---|
| 服务起不来，日志说缺缓存 | 没建行业映射 | `python scripts/build_industry_map.py` |
| 页面显示「取数失败」 | 后端挂了，且浏览器直连也失败（断网 / 腾讯挂了） | 看服务日志 `runtime/logs/heatmap.log` |
| 页面显示「静态模式」 | 正常：没有后端，走的浏览器直连 | 无需处理。本地想走后端就起服务 |
| 数字不动 | **休市**。收盘后腾讯返回最后一口数据 | 看右上角有没有「休市 · 收盘快照」 |
| 本地和线上数字不一样 | **两份实现口径分叉了** | 按 05 第一节对齐两边 |
| 云图方块是黑边/露底色 | `clampView()` 漏了某处调用 | 检查四处调用点 |
| 放大后字很小 | 又出现了绝对像素上限 | 改成按方块屏幕尺寸的比例 |
| 拖拽卡 | 每块都在 clip() | 去掉 clip，靠 1px 缝隙分隔 |
| 全市场只有 5222 只 | 导出时漏了代码表 | 导出要取 **代码表 ∪ 行业映射** |
| 请求随机返回旧数据 | 端口上有两个进程 | `netstat -ano \| grep 8770` 清干净再起 |
| 本地某个静态文件 404 | 后缀不在白名单 | 加进 `ALLOWED_SUFFIX` |

### 常用的排查命令

```bash
# 服务状态（刷新次数 / 耗时 / 最后错误）
curl -s http://127.0.0.1:8770/api/heatmap/status

# 板块强度原始 JSON（看前几个板块）
curl -s http://127.0.0.1:8770/api/sector/strength | head -c 400

# 端口上到底有几个进程（Windows 允许多重绑定，必须查）
netstat -ano | grep 8770

# 服务日志
tail -40 runtime/logs/heatmap.log

# 板块快照攒了多少条（每 5 分钟一条）
wc -l runtime/data/sector/snapshots.jsonl
```
