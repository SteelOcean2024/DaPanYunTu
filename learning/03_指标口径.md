# 03 · 指标口径（每个数字的来历）

> **这一篇是权威定义。** 前端 JS 与后端 Python 的每一处计算都必须与本篇一致。
> 改动口径时，先改这里，再改两边代码，最后重跑对齐验证。

---

## 零、全局约定（最容易错的地方）

| 约定 | 说明 |
|---|---|
| **代码格式** | 内部一律用纯 6 位数字（`600000`），只在调外部接口时转 `sh600000`。混用会导致「查不到，静默返回空」——这类 bug 不报错，极难查 |
| **涨跌幅单位** | **百分数**。`-2.61` 表示 −2.61%，不是 −0.0261 |
| **金额单位** | **元**。上游已把腾讯的「万元/亿元」换算好了 |
| **颜色习惯** | 红涨绿跌（A 股习惯，与欧美相反） |
| **交易所前缀** | 直接取报文里的 `v_sh600000` 前缀，**绝不用代码反推** |

### 为什么不能用代码反推交易所

指数代码规则和个股**完全不同**：

- 深证成指 `399001` → 从代码反推不出来（前缀 `39` 不在任何规则里）；
- 上证指数 `000001` 和「平安银行」`000001` **代码相同**，反推必然撞车。

所以 `exchange_of()` 只服务个股；指数一律从数据源的市场前缀判断。

## 一、云图（`/api/heatmap/treemap`）

### 1. `value` —— 面积

由 `metric` 决定取哪个字段：

| metric | 面积代表 | 前端标签 |
|---|---|---|
| `total_mcap`（默认） | 总市值 | 总市值 |
| `float_mcap` | 流通市值 | 流通市值 |
| `amount` | 当日成交额 | 成交额 |

**过滤规则**：`value <= 0` 的个股直接剔除。
停牌股成交额为 0，保留会让方块退化成一条线，前端要处理零宽矩形——不如在这里丢掉。

### 2. `changePct` —— 颜色（板块级）

**按面积值加权**，不是简单平均：

```
板块涨跌幅 = Σ(value_i × change_pct_i) / Σ(value_i)
```

权重全为 0 时回落到算术平均（避免除零）。

**为什么必须加权**：一只 20 亿的小票和 2 万亿的工商银行**权重相同**的话，
板块颜色会完全失真——小票涨 10% 能把一个跌 3% 的板块染成红的。

个股方块本身的颜色用**个股自己的** `change_pct`，不加权。

### 3. `summary` —— 顶部汇总

| 字段 | 定义 |
|---|---|
| `advanceCount` | `change_pct > 0` 的家数 |
| `declineCount` | `change_pct < 0` 的家数 |
| `flatCount` | 等于 0 的家数（含停牌，但停牌已被 value 过滤掉） |
| `limitUpCount` | `price >= limit_up − 0.005` 且 `limit_up > 0` 的家数 |
| `limitDownCount` | `price <= limit_down + 0.005` 且 `limit_down > 0` 的家数 |
| `turnoverAmount` | `Σ amount` |
| `indexChangePct` | 全市场按总市值加权的涨跌幅 |
| `indexes` | 8 个指数的 `{price, changePct}` |

**涨停判定为什么要 0.005 容差**：浮点比较会漏掉「现价正好等于涨停价」的票。
1 分钱以内算触及。

### 4. 节点结构

```
{ market, period, metric, metricLabel, updatedAt, stockCount, boardCount,
  summary: {...},
  nodes: [                        # 一级行业，按 value 降序
    { code, name, value, changePct, stockCount,
      children: [                 # 二级行业，按 value 降序
        { ...同上,
          children: [             # 个股，按 value 降序
            { code: "600000.SH", name, value, price, changePct,
              turnoverAmount, totalMarketCap, floatMarketCap,
              boardName, subBoardName } ] } ] } ] }
```

**排序为什么重要**：前端按顺序切分矩形，顺序稳定则每次刷新方块位置不会乱跳。

## 二、板块强度（`/api/sector/strength`）

对每个行业（一级 31 个 / 二级 131 个）算一组指标。
`level` 为 `l1` / `l2` 两个数组，**按 `rsMedian` 降序**。

### `medianPct` —— 中位数涨跌幅 ⭐

```
板块成分股 change_pct 的中位数
```

**为什么要中位数而不是加权**：它代表「**典型个股**」。
中石油涨 ≠ 石油产业涨。加权平均代表的是「指数」，中位数代表的是「随便挑一只票会怎样」。

偶数个成分股时取中间两个的平均。

### `capwPct` —— 市值加权涨跌幅

```
capwPct = Σ(total_mcap_i × change_pct_i) / Σ(total_mcap_i)
```

指数口径。权重全 0 时回落算术平均。

### `spread` —— 大票还是小票在动

```
spread = capwPct − medianPct
```

- `spread > 0`：**权重行情**（大票涨得比小票多）
- `spread ≈ 0`：**普涨普跌**
- `spread < 0`：**小票在拉**

### `breadth` —— 宽度 ⭐

```
breadth = upCount / stockCount      # 0 ~ 1
```

**判读阈值**（前端会据此把进度条变绿）：

| breadth | 含义 |
|---|---|
| ≥ 70% | 全板块在动，**真行情** |
| 40% ~ 70% | 有分歧 |
| ≤ 40% | 只有少数龙头在拉，**别当板块行情** |

### `rsMedian` —— 相对强度 ⭐⭐（排序主键）

```
rsMedian = medianPct − 全市场.medianPct
```

**这是整页最重要的一个数**。普跌日所有板块的 `medianPct` 都是负的，
「谁跌得少」才是有效信息——`rsMedian > 0` 就是跑赢大盘。

### `rsCapw` —— 指数口径的相对强度

```
rsCapw = capwPct − 全市场.capwPct
```

### `amountShare` —— 资金占比 ⭐

```
amountShare = 板块金额 / 全市场金额      # 0 ~ 1，所有板块之和 = 1
```

**它比涨跌幅更早**：涨跌幅是结果，资金占比是原因。
产业级消息出来那天，相关板块的资金占比会先跳，价格随后才跟上。

**注意**：全市场那一行的 `amountShare` 恒为 `1.0`（它自己除以自己）。

### `limitUpCount` —— 涨停家数

判定同云图 summary：`price >= limit_up − 0.005` 且 `limit_up > 0`。

### `leader*` —— 龙头

```
leaderCode / leaderName / leaderPct = 板块内 amount 最大的那只票
```

「宽度低 + 龙头大涨」就是典型的**龙头独走**。

### `upCount` / `downCount` / `flatCount` / `stockCount`

宽度的原始数据。`upCount + downCount + flatCount == stockCount`。

## 三、前端渲染口径

### 颜色映射（`COLOR_STOPS`）

**从参考实现（大盘云图）的实际色块填充色逐点采样**得到的，不是自己调的。

| 涨跌幅 | 颜色 |
|---|---|
| 0% | `#414554`（暗蓝灰） |
| ±4% | 最鲜艳（绿 `#0ad648` / 红 `#f53639`） |

**关键特征：两端鲜艳、中间暗。** 早期版本做成了「越极端越暗」，方向反了——
满屏大跌时整张图糊成一片深色，「哪里跌得最狠」反而看不出来。

### 字号

**字号只取决于方块的「屏幕尺寸」，与缩放无关。**

```
字号 / 方块高 = 0.20（四档模式各有自己的比例）
```

四档布局（按屏幕尺寸）：

| 屏幕尺寸 | 布局 |
|---|---|
| ≥ 56 × 46 | 三行：名称 / 涨跌幅 / 价格 |
| ≥ 24 × 22 | 两行：名称 / 涨跌幅 |
| ≥ 34 × 13 | 一行：名称 + 涨跌幅（左右对齐） |
| ≥ 13 × 10 | 一行：名称（放不下就截断） |

字号下限 **5.5 CSS px**——因为 canvas 是 DPR=2 的背衬，实际渲染成 11 设备像素，
在屏幕上完全看得清。这正是参考实现能把全市场铺满还看得清字的原因。

### 缩放与平移的边界

- `MIN_SCALE = 1`：**全图就是最小缩放**。布局在 scale=1 时已经正好铺满画布，
  再缩小只会露底色，没有任何信息量。
- **平移夹紧**：`tx ∈ [W×(1−scale), 0]`。scale=1 时退化成 `tx == 0`，即全图状态下拖不动——
  这是对的，此时本来就没有可拖的余量。

两个规则都写在 `clampView()` 里，且在**四处**调用：滚轮后、拖拽每帧、聚焦后、窗口重排后。
漏掉任何一处，那条路径上就会重新露出黑边。
