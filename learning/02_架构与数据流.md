**关键点**：前端是同一套，只是数据来源不同。页面采用「**后端优先、失败转浏览器直连**」——
先请求 `/api/...`，拿不到（404/网络错误）就自动切到浏览器直连。
所以你不需要为本地和线上维护两份页面。

## 二、为什么本地要分「慢路径 / 快路径」

```
        慢路径（几分钟级，缓存 7 天）
        ┌──────────────────────────────────────┐
        │ 申万行业树  31 个一级 / 131 个二级      │
        │ 成分股      index_component_sw        │
        │ 全市场代码表 stock_info_a_code_name    │
        └───────────────┬──────────────────────┘
                        │  runtime/data/industry/*.parquet
                        │  runtime/data/heatmap/*.parquet
                        ▼
        快路径（秒级，后台线程每 5 秒一轮）
        ┌──────────────────────────────────────┐
        │ 腾讯批量行情  5580 只 / 约 1.1 秒       │
        │   ↓ 挂行业                            │
        │ 组装 treemap + 板块强度 → 序列化成 bytes│
        └───────────────┬──────────────────────┘
                        │  HTTP（只读内存快照）
                        ▼
                   浏览器
```

**慢/快分离是「实时」能做成的唯一原因**：行业归属几个月才变一次，拉一次缓存起来；
每轮刷新只补价格和市值。否则每 5 秒拉一次 131 个行业的成分股（50 秒一轮），实时就是空话。

### 为什么 HTTP 层只读内存快照

`src/heatmap/service.py` 用后台线程每 5 秒拉一次行情，把结果**预先序列化成 bytes** 存内存；
HTTP 请求来了只是把 bytes 写回 socket，不做任何计算、不碰网络。三个好处：

1. 三个浏览器标签页不会把腾讯接口打成 3 倍流量；
2. 多个客户端看到的是**同一份**快照，不会出现「同一时刻不同标签页数字不一样」；
3. 网络抖动时保留上一份好数据，而不是把错误页甩给用户。

## 三、线上（纯静态）怎么做到实时

### 技术关键

腾讯行情接口**不给 CORS 头**，普通的 `fetch()` 会被浏览器拦掉。
但它的报文是**赋值给全局变量的脚本**：

```js
v_sh600000="1~浦发银行~600000~10.40~10.21~...";
```

而 **`<script>` 标签不受同源策略限制**。所以：

```js
const s = document.createElement("script");
s.src = "https://qt.gtimg.cn/q=sh600000,sz000001";
s.onload = () => { /* 读 window.v_sh600000 */ };
```

就能拿到行情。这不是 hack，是这些老接口的**设计形态**（JSONP 的变种）。

### 代价：两份实现

`web/shared/market.js` 是下面三个 Python 模块的**第二份实现**：

| Python | JavaScript | 作用 |
|---|---|---|
| `src/data/codes.py` 的 `exchange_of` | `exchangeOf` | 6 位代码 → `sh/sz/bj` 前缀 |
| `src/heatmap/quotes.py` 的 `_parse_line` | `parseQuote` | 解析腾讯报文 |
| `src/analysis/sector.py` | `computeSectorStrength` | 板块强度指标 |
| `src/heatmap/treemap.py` | `buildTreemap` | 云图嵌套树组装 |

**这是必须付的代价**，因为纯静态托管跑不了 Python。
两边已经逐项对齐验证过（全市场汇总、32 个一级行业、132 个二级行业、5580 只个股，零差异），
但**改动任何一边的口径，另一边必须一起改**。

## 五、一次刷新的完整时序（本地）

```
后台线程（每 5 秒）
  1. quotes.fetch_quotes(codes)          腾讯批量，5580 只 / 1.1 秒
  2. industry.attach_industry(df, map)   给每只票挂上 l1_name / l2_name
  3. treemap.build_treemap(...)          组装嵌套树 + 汇总
  4. sector.compute_sector_strength(...) 板块强度指标
  5. json.dumps(...).encode()            预先序列化成 bytes
  6. 加锁写入 self._treemap_json / self._sector_json
  7. sector.append_snapshot(...)         每 5 分钟落一条快照（锁外，磁盘慢不拖住读）

浏览器（每 5 秒）
  GET /api/heatmap/treemap?metric=total_mcap  → 直接回 bytes
  → buildLayout() → draw()
```

### 切换面积口径为什么不重新拉行情

`GET /api/heatmap/treemap?metric=amount` 时，服务用**最近一次的合并行情**就地重算
（5500 行约几十毫秒），结果缓存进 `_metric_cache`。所以前端的「总市值/流通市值/成交额」
切换是秒回的。线上同理：`buildTreemap(metric)` 复用已缓存的行情。

## 六、接口一览

| 路径 | 说明 |
|---|---|
| `GET /` | 云图页面 |
| `GET /sector` | 行业情况页面 |
| `GET /style.css` `/app.js` | 云图静态资源 |
| `GET /shared/*` `/data/*` | 前端共享资源与静态数据 |
| `GET /api/heatmap/treemap?metric=` | 云图数据（嵌套树 + 汇总） |
| `GET /api/heatmap/summary` | 只要汇总 |
| `GET /api/heatmap/status` | 服务状态（刷新次数、耗时、错误） |
| `GET /api/sector/strength` | 板块强度（`{updatedAt, market, l1[], l2[]}`） |

服务端对静态文件有**后缀白名单**（`.html .css .js .json .ico .png .svg .map`）
和**目录穿越防护**（解析后必须仍在目标目录内）。加新资源类型记得改白名单。
