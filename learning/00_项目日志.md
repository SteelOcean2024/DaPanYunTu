## 二、阶段一：把云图做出来（11-12）

### 起因

目标是复刻 `beta.dapanyuntu.com` 这张图：一级行业 → 二级行业 → 个股的三层 treemap，
面积 = 市值、颜色 = 涨跌幅、实时刷新。

### 关键决策：不扒别人的接口

参考站的 `/api/heatmap/treemap` 确实能直接调（一次返回 5566 只的完整 JSON），
但那是别人的商业服务，热链随时会断。所以数据链路全部重做。

### 选数据源：为什么是腾讯

| 候选 | 实测 | 结论 |
|---|---|---|
| 东方财富 push2 | 一次返回全市场，但**按 IP 限流**（触发后 5~40 分钟） | ❌ 5 秒刷一轮必死 |
| 腾讯 `qt.gtimg.cn` | **5580 只 / 1.92 秒**（后优化到 1.1 秒），不封 | ✅ 采用 |
| 新浪 | 可用 | 作为备用 |

### 关键决策：慢/快路径分离

行业归属几个月才变一次（申万一/二级 31+131，一次拉全约 50 秒），
所以**拉一次缓存 7 天**；每轮刷新只补价格和市值。
**这是「实时」能做成的唯一原因**——否则每 5 秒拉 131 个行业的成分股，实时就是空话。

### 踩的坑（详见 `05_注意事项.md`）

- 交易所不能用代码反推（深证成指 `399001` 被静默丢弃、`000001` 与平安银行撞车）
- 北交所 `920xxx` 新号段整批丢失
- 腾讯字段单位（成交额万元 / 市值亿元 / 成交量手）
- squarified 必须沿**短边**铺，写反了会渲染成一层层横条

## 三、阶段二：三轮「做得不行」的返工（11-12 ~ 11-13）

### 第 1 轮：「马赛克」

**症状**：用户说「别人都能看清楚字，你这纯纯马赛克」。

**排查**：先量自己的数据——5580 个方块里只有 **71 个有字（1.3%）**，中位方块只有 6×5 像素。
然后 hook 参考站的 canvas 数它画了多少东西：它也渲染了 5698 个方块、中位 5.1 像素，
但有 **903 次 fillText**。

**根因**：参考站字号能小到 **5.5 CSS px**（canvas 是 DPR=2 背衬，实际 11 设备像素，看得清），
而第一版下限卡在 6.5px，放不下就整块不画。

**顺带发现一个误判**：一开始以为「布局不对」（拿参考站的 382 个大方块比我的 170 个），
其实参考站那个数里**含了 164 个板块标题带**——补上后两边几乎一样（785 vs 768）。差点去改一个没坏的布局算法。

**修法**：四级降级（三行 / 两行 / 一行 / 只画名字），小方块截断时不加省略号。
有字方块 71 → **845**，fillText 142 → 1161。

### 第 2 轮：「没有伸缩性 / 点不开链接 / 颜色丑」

三条一起报的，逐条查：

| 投诉 | 根因 | 修法 |
|---|---|---|
| 没有伸缩性 | 侧栏固定 236px，窄屏把画布挤成一条缝 | `@media (max-width:900px)` 改浮层抽屉；用 `ResizeObserver` 监听**画布容器**而非 `window.resize` |
| 点不开链接 | `window.open(url, "_blank", "noopener")` 的第三参数非空，Chrome 按**弹出式窗口**处理 | 改用 `<a target="_blank">.click()`。**实测复现**：插桩发现 `window.open` 被调用了但返回 `null`、浏览器里什么都没多出来 |
| 颜色丑 | 色阶方向反了（做成了「越极端越暗」） | 从参考站**实际色块填充色**逐点采样重建色阶。注意：**它的图例和它的实际填色不是同一套映射**，照图例抄会抄错 |

### 第 3 轮：「缩小后周围全是黑的」「放大后字不跟着长」

| 投诉 | 根因 | 修法 |
|---|---|---|
| 缩小露黑底 | `MIN_SCALE = 0.5`，但布局在 `scale=1` 时已铺满画布 | `MIN_SCALE = 1` + `clampView()` 夹紧平移（**四处调用**） |
| 放大后字很小 | 单位混用：`availW` 是世界单位、字号是屏幕单位，估算**漏乘 `scale`**；外加四档字号的**绝对**像素上限把字号钉死 | 补上 `* scale`；把绝对上限换成「按方块屏幕尺寸的比例」 |

实测数据（建设银行这一块）：

| 缩放 | 方块屏幕尺寸 | 修复前字号 | 修复后字号 |
|---|---|---|---|
| 1× | 331 × 411 | 30 px | 76 px |
| 4× | 1325 × 1645 | 30 px | 324 px |
| 40× | 13252 × 16446 | 30 px | 3312 px |

修复后「字号 / 方块高」恒为 0.20，与缩放无关。

## 五、阶段五：行业情况面板（11-13 下午）

### 起因

用户提出：「产业有风波的话，影响的是**产业**，比如黄仁勋那种事件。我就想有个衡量标杆。」

### 设计结论

这是**共同因子**问题：`个股收益 = α（自身故事） + β × 板块波动（产业风波） + ε`。
要量的是 β 那一项。

指标选了这些（完整定义见 `03_指标口径.md`）：

| 指标 | 回答 |
|---|---|
| `rsMedian` | **谁跑赢大盘**（排序主键） |
| `breadth` | **真动还是假动**（≥70% 才算板块行情） |
| `amountShare` | **钱在哪**（比涨跌幅更早） |
| `medianPct` | 典型个股的涨跌（不是加权） |
| `leader*` | 谁在动 |

### 关键架构决策：新开页面还是改云图

**保留云图不动，新开 `/sector`。** 理由：

1. 云图是当时唯一被验证过的东西，新方案口径还没定，不该拿它当试验场；
2. 新方案的主体是**新形态**（排行表 + 时序），不是云图的变体；
3. **数据与指标只有一份**（服务端算），所以两个页面不等于两份实现。

### 第二轮反馈：用户说「我没理解」

用户反馈：「行业板块能说明什么？我没理解，你得有解释，并且有实时刷新。」

两件事都查了，结果都成立但方向不同：

1. **实时刷新是好的**——实测时间戳 15:10:10 → 15:10:24 → 15:10:35 自己往前走。
   用户觉得没刷新，是因为**当时已收盘（15:10），数字本来就是冻的，而页面上没说这件事**。
2. **页面只给数字，不告诉人怎么读。** 这是真问题。

**修法**：加了三层解释——自动生成的结论条、「怎么看这一页」说明块、表头副标题 + hover 提示；
并让「活着」这件事可见（时钟每秒自己走 + 盘中/休市标识）。

## 六、阶段六：纯静态部署（11-13 傍晚）

### 用户要求

「在我的 GitHub 上新建一个 DaPanYunTu 项目…将代码上传。然后将网页部署一下。」

### 关键技术发现

GitHub Pages 只能跑静态文件，跑不了 Python——**除非前端自己取数**。
腾讯行情接口不给 CORS 头，但它是「赋值给全局变量的脚本」（`v_sh600000="..."`），
而 **`<script>` 标签不受同源策略限制**。实测确认可行后，写了 `web/shared/market.js`。

### 写成第二份实现的代价

这是**唯一可行**的路（纯静态托管跑不了 Python），但必须清楚：

- `market.js` 是 `codes.py` + `quotes.py` + `sector.py` + `treemap.py` 的第二份实现；
- 两份逻辑必须同步维护，改一边要改另一边；
- 已逐项对齐验证（全市场汇总、32 个一级行业、132 个二级行业、5580 只个股，零差异）。

### 过程中发现并修掉的一个真 bug

第一版导出的行业映射只含**有行业归属的 5222 只**，漏了代码表里的 5580 只全集。
结果浏览器算的「全市场中位数」是 5222 只的中位数（−1.96%），比后端（−2.00%）偏 0.04，
**所有板块的 RS 整体偏移 0.04**。

**修法**：导出取 **代码表 ∪ 行业映射**，未归上行业的记为「未分类」——与后端 `attach_industry()` 一致。
修完两边逐项零差异。

### 部署卡住的两次

| 卡点 | 原因 | 解决 |
|---|---|---|
| 建不了仓库 | 本机没有 GitHub token，也没有 `gh` CLI；SSH 密钥**能推不能建** | 用户手动建空仓库 |
| 工作流 `configure-pages` 失败 | **Pages 站点从未创建**。`GITHUB_TOKEN` 没有 `administration` 权限，`enablement: true` 也救不了 | 用户在 Settings → Pages 选 **GitHub Actions** |

两次都是**只能人工做的一步**，代码层面绕不过去。
