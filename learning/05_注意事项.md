# 05 · 注意事项（最重要的一篇）

> 这一篇记录**所有已知的坑、必须遵守的约定、以及红线**。
> 大部分是从真实故障里总结出来的，不是理论。

## ⚠️ 一、最大的红线：两份实现必须同步

| | 权威实现 | 用途 |
|---|---|---|
| Python | src/（codes / quotes / sector / treemap） | 本地与服务器 |
| JavaScript | web/shared/market.js | 纯静态托管（GitHub Pages） |

**改任何一边的口径，另一边必须一起改。** 否则会出现「本地显示 −2.00%，线上显示 −1.96%」
这种最难查的 bug——因为它不报错，只是数字悄悄不一样。

### 已经发生过一次

第一版导出行业映射时，只导出了「有行业归属」的 5222 只，漏掉代码表里的 5580 只全集。
结果浏览器算出来的**全市场中位数是 5222 只的中位数**（−1.96%），比后端（−2.00%）偏 0.04，
**所有板块的 RS 整体偏移 0.04**。

修法：导出时取 **代码表 ∪ 行业映射**，未归上行业的记为「未分类」——与后端 attach_industry() 口径一致。

### 怎么验证两边一致

打开 /sector 或 /heatmap（页面已加载 market.js），在控制台跑：

```js
await MarketData.fetchAll({ base: "../" });
const js = MarketData.buildTreemap("total_mcap");
const py = await (await fetch("/api/heatmap/treemap?metric=total_mcap")).json();
// 比较 stockCount / summary / 每个 board 的 value 与 changePct
```

对齐标准：stockCount、summary 各项、每个板块的 value / changePct / stockCount / children.length 全部相同。

## 二、单位（历史上差过好几个数量级）

| 字段 | 单位 | 坑 |
|---|---|---|
| change_pct | **百分数** | -2.61 是 −2.61%，**不是** −0.0261 |
| 腾讯 [37] 成交额 | **万元** | ×1e4 |
| 腾讯 [44][45] 市值 | **亿元** | ×1e8 |
| 腾讯 [36] 成交量 | **手** | ×100 → 股。但腾讯/新浪另有接口直接返回股，**用前先验证** |
| 换手率 | **比率** | 0.0016 是 0.16%，要 ×100 |

**成交量单位踩过最惨的一次**：曾以为腾讯的 volume 是「手」，又乘了 100，导致数据虚高 100 倍。
最快的自检方法：**成交额 ÷ 成交量 应该约等于均价**。差 100 倍就是单位错了。

## 四、数据源

### 东方财富会限流，不要用在实时链路上

push2 接口一次能返回全市场，但**按 IP 限流**，触发后 **5~40 分钟不可用**。
云图要 5 秒刷一轮，用东财必死。本项目全程用腾讯批量接口（不封，5580 只约 1.1 秒）。

### 腾讯接口的形状

- 报文是 v_sh600000="1~浦发银行~..."; —— **赋值给全局变量的脚本**。
- 所以 script 标签能加载，**不受同源策略限制**（线上纯静态部署就靠这个）。
- **不给 CORS 头**，所以 fetch() 会被浏览器拦——不要在线上试图用 fetch 直连。
- 字段按下标取，**少于 49 个字段的要丢弃**（新股 / 异常报文）。
- 现价 ≤ 0 的要丢弃（停牌 / 退市 / 无行情）。**一只坏票不能毁掉整个快照。**

## 五、计算口径的坑

| 坑 | 后果 | 正解 |
|---|---|---|
| 板块涨跌幅用简单平均 | 一只 20 亿的小票和 2 万亿的工行权重相同，板块颜色完全失真 | **按面积值加权** |
| 用加权平均代替中位数看「板块」 | 中石油涨 ≠ 石油产业涨 | 板块强弱看 **medianPct**；capwPct 是另一个口径 |
| 保留 value <= 0 的票 | 方块退化成一条线，前端要处理零宽矩形 | **组装前剔除** |
| 涨停判定不留容差 | 浮点比较漏掉「现价正好等于涨停价」的票 | price >= limit_up - 0.005 |
| 丢掉「未分类」 | 板块家数之和对不上大盘，用户以为数据缺了 | **如实呈现**，它是虚拟板块不是垃圾 |

## 六、前端渲染的坑

### 1. squarified 必须沿**短边**铺

写成沿长边铺的话，渲染出来是**一层层横条**而不是方块。这是最容易写反的一行。

### 2. 字号有「世界单位 / 屏幕单位」之分

canvas 处在 ctx.scale(scale, scale) 变换下，所以：

- setFontScreen(f, ...) 里的 f 是**屏幕**字号（内部除以 scale 才是世界字号）；
- availW = t.w - ... 是**世界**单位。

**踩过的坑**：初始估算写成 availW / textWeightUnits(text)，**漏乘 scale**，
导致放大后方块越来越大、字却停在原尺寸，四周空一大片，看起来像「马赛克」。

### 3. 不要用绝对像素上限

四档字号和标题带原本都有**绝对**屏幕像素上限（30 / 14 / 11 / 10 / 15 px），
放大后会把字号**钉死**。必须换成「按方块屏幕尺寸的**比例**」——比例与缩放无关，绝对上限才有问题。

### 4. 缩放与平移都要夹紧

- MIN_SCALE = 1：布局在 scale=1 时已铺满画布，再缩小只会露底色。
- clampView() 必须在**四处**调用：滚轮后、拖拽每帧、focusRect 后、resizeCanvas 后。
  **漏掉任何一处，那条路径上就会重新露出黑边。**

### 5. window.open 不要传第三个参数

window.open(url, "_blank", "noopener") —— 第三个参数一旦非空，
Chrome 按**弹出式窗口**处理：容易被弹窗拦截器吃掉，或开成独立小窗落在主窗口后面，
用户看到的就是「点了没反应」。改用 a 标签：target="_blank" rel="noopener"，然后 .click()。

**附带一个陷阱**：这种写法返回 null 是**设计如此**（noopener 就没有 opener 引用），
不能用返回值判断是否被拦截。要看浏览器里是否真的多了 target（CDP Target.getTargets）。

### 6. 配色方向

是「**两端鲜艳、中间暗**」（0% 暗蓝灰 #414554，±4% 最鲜艳），
**不是**「越极端越暗」。方向反了，满屏大跌会糊成一片深色。

### 7. 不要给每个方块加 ctx.clip()

标签从 71 个涨到 845 个之后，拖拽掉到 26 fps。根因是每个有标签的方块都做了
save → rect → clip → restore，而 clip() 很贵**而且没解决问题**——
文字本来就按尺寸算好不会溢出，真正隔开相邻文字的是那 1px 缝隙。去掉后 95 fps。

## 九、其他约定

- **runtime/ 不入库**（.gitignore）。行业映射缓存是构建产物，用脚本重建。
- **板块快照每 5 分钟一条**（SNAPSHOT_INTERVAL_SEC）。后台是 5 秒一轮，不限流一天能写几万条，
  而盘中没有额外信息量。用 JSONL 是因为盘中**追加写**最合适，收盘后再压成日线。
- **落盘写在锁外**。磁盘慢不该拖住读快照的请求。
- **后台线程绝不能因异常退出**：_loop() 里捕获所有异常，refresh_once() 失败时保留上一份快照。
- **行业映射不覆盖全部 A 股**（北交所、次新股），约 358 只归「未分类」。这是如实呈现，不是 bug。
- **节假日不做判断**：isTradingNow() 只看星期与钟点，节假日会显示成盘中。页面帮助里写明了。

## 十、三端适配（PC / iPad / 手机）

### 1. 触摸手势必须**显式接管**，不能只写鼠标事件

只写 `mousemove` / `mousedown` / `wheel` 的话，在触摸设备上：

| 操作 | 实际发生的事 |
|---|---|
| 拖拽 | 浏览器拿去**滚动页面**，canvas 收不到 |
| 捏合 | 浏览器拿去**缩放页面本身**，canvas 收不到 |
| 轻点 | 能靠浏览器合成的 `click` 生效（唯一侥幸能用的） |

**正解**：canvas 上 `touch-action: none`，再显式处理 `touchstart/move/end`——
单指平移、双指捏合（以两指中点为锚点）、轻点选中。

还有个细节：`touchend` 里要 `preventDefault()`，否则浏览器会再合成一次 `click`，**点一次开两次**。

### 2. 触摸判定要用 `pointer: coarse`，**不要用宽度断点**

iPad 横屏宽 1024——按宽度判断会把它当桌面端，按钮只有 30px 高，手指根本点不准。
`@media (pointer: coarse)` 问的是「输入设备粗不粗」，这才是对的维度。

点击目标下限 **44px**（Apple HIG / Material 通用值）。

### 3. 手机端表格必须变卡片

8 列的表格在 390px 上要**横向滚 681px** 才看得完，每行还只有 24px 高。

**做法**：`@media (max-width: 700px)` 下把 `tr` 变卡片、隐藏 `thead`，
每个 `td` 用 `::before { content: attr(data-label) }` 显示列名——
列名由 JS 写在 `td.dataset.label` 上（见 `render()` 里的 `lab()`）。

实测：表格 681px → 卡片自适应，`main` 的 `scrollWidth` 从 697 降到 390（不再横向滚）。

### 4. 说明块在手机上必须默认收起

「怎么看这一页」默认展开时，在 390×844 的手机上**占满整整两屏**——
打开页面看到全是文字，**数据被顶到屏幕外**，用户根本不知道下面是表格。

**做法**：HTML 里不带 `open`，用脚本按宽度决定：

```js
if (innerWidth >= 900) document.getElementById("help").open = true;
```

### 5. 性能：先量再优化

`draw()` 一帧的开销实测（5580 个方块，全部可见时）：

| 环境 | 每帧 | 帧率 |
|---|---|---|
| 干净浏览器，canvas 1028×727 | **10.1 ms** | 99 fps |
| iPad 模拟，canvas 768×946 | **16 ms** | 62 fps |
| iPhone 模拟，canvas 390×766 | **9.9 ms** | 100 fps |

**结论：不需要优化。** 第一次测出 32ms 是因为**首次绘制要加载字体**，
预热之后就降到 13~16ms。差点为一个不存在的问题去改渲染架构。

用 `pointer/width` 之外的原则：**先量，别猜。**

## 十一、悬停详情面板（K 线 + 成分股列表）

### 关键前提：腾讯的 K 线接口**允许跨域**

这是整个面板能纯静态实现的原因。实测（浏览器内直接 fetch）：

| 接口 | 结果 |
|---|---|
| 腾讯 `web.ifzq.gtimg.cn/appstock/app/fqkline/get` | ✅ **200，允许跨域** |
| 腾讯 `web.ifzq.gtimg.cn/appstock/app/minute/query`（分时） | ✅ 200，允许跨域 |
| 新浪 `money.finance.sina.com.cn/.../getKLineData` | ❌ 被 CORS 挡（script 标签能加载，但返回的是 JSON 不是 JSONP，用不了） |

**所以画 K 线不需要后端。** 返回行格式是 `[日期, 开, 收, 高, 低, 量]`
（注意：**开、收、高、低**，不是常见的 开高低收）。

### 三个设计决定

1. **面板覆盖在画布右侧，不挤压画布。** 挤压的话鼠标一动云图就重排，
   方块位置乱跳，完全没法用。
2. **只在桌面端显示。** 触摸设备没有 hover，面板会一直挡着云图；
   窄屏（<1100px）同理。CSS 里直接 `display: none !important`。
3. **悬停 110ms 防抖 + K 线按代码缓存。** 鼠标划过一排方块时不该一路发请求。

### 面板内容

| 区域 | 内容 |
|---|---|
| 头部 | 个股名 + 代码 + 行业路径（一级 › 二级） |
| 行情 | 现价 / 涨跌幅 / 成交额 / 总市值 |
| K 线 | 日 K（前复权，120 根）+ MA5 / MA10 / MA30，自算 |
| 板块行 | 所属二级行业 + 家数 + 涨跌家数 + 行业涨跌幅 |
| 排序 | 涨幅 / 成交额 / 总市值 / 名称 |
| 列表 | 该二级行业全部成分股，**点击打开行情页** |

### 没做的

- **每行的分时缩略图**（参考站有）。要给 48 行各拉一次分时，48 个请求太慢，不值。
- **悬停板块标题带**只显示该板块列表、不显示 K 线。（个股才有 K 线）

## 十二、K 线面板的「慢」是怎么解决的

### 先量：慢的不是网络

第一反应是网络慢，实测**不是**（线上浏览器内直接 fetch）：

| 代码 | 冷请求耗时 |
|---|---|
| sh600028 | 125 ms |
| sz000651 | 169 ms |
| sh601398 | 97 ms |
| sz002594 | 104 ms |
| sh600887 | 100 ms |

**97~169 ms，网络没问题。** 慢在交互链路：

```
鼠标停住 → 等 110ms 防抖 → 才发请求 → 等 ~150ms 网络 → 画图
                     ↑ 这 110ms 是纯等待，什么也没干
```

### 修法：让请求和防抖**并行**，而不是串行

| 改动 | 效果 |
|---|---|
| 悬停换目标时**立刻**预取 K 线（不等防抖） | 防抖结束时数据通常已到，省掉整段网络等待 |
| `fetchKline` 加**在飞请求去重**（`_klinePending`） | 预取与正式请求并成一次，不会发两次 |
| 防抖 110ms → **70ms** | 缩短纯等待 |
| `<head>` 里 `preconnect` 两个行情域名 | 省掉首次的 DNS + TLS 握手 |

### 实测（本机，浏览器内计时到 K 线画出来）

| | 改前 | 改后 |
|---|---|---|
| 首次冷悬停 | 244 ms | **152 ms** |
| 之后每次 | — | **34 ~ 35 ms** |

第一次仍需一次真实网络往返（约 150ms，这是物理下限）；
之后因为预取赶在防抖结束前完成，**基本感觉不到加载**。

### 面板改成跟随指针浮动

原来是固定在右侧（`position: absolute; right: 0`），现在改成跟随指针（`position: fixed` + 动态 left/top）。

三个实现要点：

1. **只在「悬停目标变了」的时候重新定位**，不是每个 mousemove 都动。
   否则面板会跟着指针抖，还会和指针抢 hover，互相打架。
2. **贴边自动翻面**：默认在指针右下方 +20px；右边放不下就翻到左侧，下边放不下就往上顶。
3. **鼠标要能移进面板**。面板不在 canvas 里，指针一移进去 canvas 就触发 `mouseleave`，
   面板会在 320ms 后自己消失，列表根本点不到。所以给面板加了 `mouseenter` 取消隐藏计时器。
